## User-visible changes from preview.9

### Worktrees now start from the latest remote default branch by default

- Creating a managed Worktree without an explicit base now discovers and fetches the remote's current default branch instead of using the local checkout's `HEAD`. The desktop and TUI forms default to **Latest default branch** and also expose **Current checkout** and **Custom local ref**. The CLI follows the same rule: omitting `--base` fetches the latest default branch; `--remote` chooses a remote, while an explicit `--base HEAD` retains the old local-checkout behavior. Successful CLI/TUI creation reports the resolved base ref and pinned commit. See the released [base-selection model](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-core/src/ui_forms.rs), [CLI](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-cli/src/main.rs), and [Git implementation](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/git.rs).
- With no remote supplied, SylvOps chooses `origin`, otherwise the sole configured remote. It fails visibly when there is no remote, when several non-`origin` remotes are ambiguous, or when discovery/fetch/authentication fails; it never silently falls back to a stale local ref. The selected remote's symbolic `HEAD` is queried on each operation, its exact branch is fetched, and the advertised commit must match the fetched commit. See [`resolve_worktree_base`](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/git.rs).
- GitHub Issue **Start Work** now previews the latest default branch of the Project's associated GitHub remote, not the root Worktree's current branch. The desktop and TUI can switch the preview to Current checkout or a custom local ref. SylvOps resolves the base again immediately before mutation and refuses to create the Worktree if the branch moved after confirmation. See the released [daemon preparation and confirmation path](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/daemon.rs) and [Start Work base identity](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-core/src/github.rs).
- Worktree-base selection changes the local IPC request shape and advances the protocol minor version from 22 to 23; it does not introduce a database migration. See the released [protocol](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-core/src/protocol.rs).

### Opening a stopped conversation resumes and attaches

- `Terminated` (user-stopped) Codex or Claude conversations are now eligible for the existing guarded resume flow when they have a verified saved conversation ID, a healthy resume-capable provider, and no newer successor. Resume still creates a new Session history record; it does not reuse or erase the stopped record. See the released [resume eligibility](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-core/src/domain.rs) and [daemon guard](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/daemon.rs).
- In both desktop and TUI, opening the terminal for any inactive but resumable conversation now starts its successor and attaches automatically. A non-resumable inactive Session instead produces an actionable error and keeps its retained history; the user must choose New Session explicitly. This is a behavior change from preview.9, where opening an inactive Session could inspect retained output without launching a provider. See the released [desktop flow](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-desktop/src/lib.rs) and [TUI flow](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/lib.rs).

### TUI terminal scrolling is restored for full-screen providers

- Attached-terminal history adds clickable **Older** and **Newer** footer controls alongside the existing wheel and Shift+PageUp/Shift+PageDown inputs. A program that requests mouse reporting receives wheel events; a full-screen program without mouse reporting receives PageUp/PageDown keys. Observers can scroll SylvOps' local history but cannot forward input to the provider. See the released [terminal router](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/terminal.rs) and [footer](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/render.rs).
- Reattachment and output-gap snapshots now preserve the active normal/alternate screen and supported input modes, so Codex scrolling continues to route correctly after recovery. Snapshots are regenerated from parser state rather than replaying raw provider OSC sequences. See the released [session snapshot implementation](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/session.rs) and [PTY contract](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/docs/architecture/pty.md).

### Attention is clearer and can make a local sound

- TUI Cards/List rows in **Needs feedback** now use a stronger orange attention surface and matching border, including with Terminal Default theme. See the released [TUI theme](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/theme.rs) and [renderer](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/render.rs).
- While the TUI is open, a Session newly entering **Needs feedback** rings the terminal bell. Windows additionally shows a native notification-area popup. Existing waiting Sessions do not alert at startup, repeated snapshots do not repeat an alert, and a later transition back into Needs feedback alerts again. Other TUI platforms currently receive only the bell. See the released [TUI notification tracker and Windows notifier](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/notifications.rs).
- Desktop Session rows and tabs now highlight **Needs feedback**, while Starting/Running Sessions show an animated ring. A newly waiting Session produces a bounded in-app message and plays a local system sound when available. Windows uses `MessageBeep`; macOS uses the fixed `/usr/bin/afplay` path; Linux tries fixed `canberra-gtk-play` or `paplay` commands. Sound work is non-blocking and bounded. See the released [desktop status presentation](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-desktop/src/lib.rs) and [sound implementation](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-desktop/src/notifications.rs).

## Security and authority implications

- **Worktree creation has a broader, visible network effect.** The same explicit Create Worktree or Start Work confirmation can now contact a configured Git remote and update one `refs/remotes/<remote>/<default-branch>` ref before local branch/worktree creation. The fetch uses `--no-tags`, `--no-recurse-submodules`, and `--no-write-fetch-head`; it does not switch or modify the registered checkout, and tests cover preservation of its uncommitted and untracked files. The daemon serializes the operation per Project. See the released [Git implementation and tests](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/git.rs).
- Remote execution remains bounded: remote names and advertised branches are validated, the requested remote must already exist, Git hooks are disabled, interactive terminal and credential-manager prompts are disabled, subprocess output is bounded, and Git commands have a five-second timeout. The code explicitly permits the configured remote's `https`, `http`, `ssh`, `git`, or `file` transport after starting from `protocol.allow=never`; therefore it can use the user's existing Git/SSH credential setup but does not store a new credential. See [`run_remote_git` and `run_git_os`](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-daemon/src/git.rs).
- **Open terminal has greater process authority for inactive conversations.** The explicit action may now launch a resume-capable provider as a successor Session before attaching. The daemon keeps the pre-existing verified-conversation, provider-health, state, and no-newer-successor guards. See the released [provider resume guard](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-core/src/provider.rs).
- Attention notifications are presentation-only. Their text uses a control-character-stripped Session display name capped at 80 characters and never includes terminal/conversation content. The TUI Windows tray icon is removed on shutdown. Desktop Unix sound commands use only fixed executable paths and fixed arguments; user/provider text is never passed to a process. See the shared [attention tracker](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-core/src/attention.rs), [TUI notifier](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/notifications.rs), and [desktop sound notifier](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-desktop/src/notifications.rs).
- Terminal scroll forwarding remains controller-only. A deliberate wheel/history action can now reach the provider as mouse or page-key input when its terminal mode calls for it; observer attachments remain read-only. Parser-derived snapshots avoid replaying arbitrary historical OSC sequences. See the released [terminal input router](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/crates/sylvops-tui/src/terminal.rs) and [PTY architecture](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/docs/architecture/pty.md).

## Release and installation status

- Preview.10 remains an **unsigned testing preview**, not an official signed application release. It publishes Windows x86_64 as a portable ZIP and Linux x86_64 as a portable archive, AppImage, and Debian package. There is no macOS package or signed native Windows installer. Windows may report an unknown publisher. [Release notice](https://github.com/devemit/sylvops/releases/tag/v0.1.0-preview.10).
- Preview builds do not receive signed in-app updates. Preview.10 must be installed explicitly from its exact release or built from source. Users should verify the matching package with the release's `SHA256SUMS`; the successful workflow also generated GitHub build-provenance attestations for the checksum, warning, and package files. See the released [`Unsigned Preview` workflow](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/.github/workflows/unsigned-preview.yml) and [successful run](https://github.com/devemit/sylvops/actions/runs/38924059981).
- The preview workflow's macOS and native Windows installer jobs are verification gates only. The published asset set intentionally excludes those packages even though all platform verification jobs passed. [Workflow jobs](https://github.com/devemit/sylvops/actions/runs/38924059981).

## Still planned, not shipped in preview.10

The released README continues to mark Claude cloud Sessions, background-agent management, Remote Control, plugins and enterprise authentication, GitHub mutations, Pull Request checkout/review flows, background polling, broader notifications, remote execution, file finding, and Git grep as planned. Terminal click/drag forwarding also remains deferred. Preview.10 does not implement those capabilities. [Released feature-status and TUI statements](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/README.md).

The released IPC document separately records connected-client SID verification as remaining defense-in-depth hardening on Windows; preview.10 retains the existing remote-client rejection, owner-only pipe DACL, and runtime-token checks. [Released IPC security contract](https://github.com/devemit/sylvops/blob/55205262a5c7b89f81912a6876e26d87f2ec5a42/docs/architecture/ipc.md).
