## User-facing changes completed in the candidate

The GitHub-work epic and all of its delivery issues, [#122](https://github.com/devemit/sylvops/issues/122) through [#130](https://github.com/devemit/sylvops/issues/130), are closed and their implementation commits are present in the candidate comparison. The TUI improvement issues [#131](https://github.com/devemit/sylvops/issues/131) through [#135](https://github.com/devemit/sylvops/issues/135) are also closed and present in that comparison.

### Desktop

- **Connect a Project to GitHub.** SylvOps discovers the user's existing authenticated `gh` CLI and lets the user explicitly associate a Project with one of that repository's validated GitHub remotes. The association persists, while SylvOps neither initiates login nor stores GitHub credentials. See [#123](https://github.com/devemit/sylvops/issues/123) and the candidate's [GitHub daemon implementation](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-daemon/src/github.rs).
- **Browse Issues and Pull Requests inside the desktop app.** A project-level surface works without an active Worktree or Session and provides separate Issue and Pull Request lists/details, filters, pagination, explicit refresh, actionable failure states, and an explicit validated **Open in browser** action. See [#125](https://github.com/devemit/sylvops/issues/125) and the [desktop GitHub surface](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-desktop/src/github_surface.rs).
- **Start isolated work from an Issue.** The guided flow previews bounded Issue context, the exact local base commit, an editable `issue/<number>-<slug>` branch, an optional Session name, and separate additional instructions. A successful run creates a managed Worktree, records the Issue as its Work Source, starts a task-capable provider Session, selects it, and opens its terminal. In this candidate, Codex is task-bootstrap capable; Shell and Claude are not. See [#127](https://github.com/devemit/sylvops/issues/127), the [provider capability source](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-daemon/src/provider.rs), and the [desktop Start Work form](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-desktop/src/forms.rs).
- **Recover and reuse Issue-driven work.** Reopening an Issue directs the user to linked local work by default; starting another Worktree is explicit. If Worktree creation succeeds but Session launch fails, SylvOps preserves the Worktree and offers Retry Session or navigation instead of rolling back valid Git state. Work Source status is shown as Not started, Worktree ready, Session active, or Session stopped. See [#128](https://github.com/devemit/sylvops/issues/128) and the [Start Work integration tests](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-test-support/tests/start_work.rs).
- **Smaller desktop trash controls.** The selected entity's removal control is now a small red, borderless, trailing-aligned icon with a target-specific accessible name and textual confirmation. It no longer has a hover tooltip. See merged [PR #149](https://github.com/devemit/sylvops/pull/149) and the [desktop UX contract](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/docs/product/desktop-ux.md).

### TUI

- **Persistent appearance settings.** `s`, the Settings header target, or the command palette opens a dedicated Settings mode. It previews and applies Terminal Default, Nord, Tokyo Night, Catppuccin, Gruvbox Dark, or Solarized Light, plus Comfortable/Compact density. Cancel or Escape restores the previous settings; applied TUI preferences persist independently from desktop preferences. See [#131](https://github.com/devemit/sylvops/issues/131) and [ADR 0017](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/docs/decisions/0017-tui-appearance-settings.md).
- **Active Sessions overview.** `4` opens a Workspace-wide view containing only Starting, Running, and Needs feedback Sessions. Needs feedback sorts first. Cards are the default and become two columns only when wide enough; List is an equivalent single-column option. Selection does not attach until Enter or **Open terminal** is used. See [#132](https://github.com/devemit/sylvops/issues/132) and the candidate [README TUI essentials](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/README.md#tui-essentials).
- **More compact, contextual chrome.** The header and footer are each one row, footer shortcuts follow the current pane/mode, and Session actions appear in their relevant context instead of as unrelated global controls. See [#133](https://github.com/devemit/sylvops/issues/133).
- **Keyboard-first Project directory browser.** Project registration now has a Browse flow starting from the TUI process's launch directory. Users can navigate child directories, Parent, Home, Unix roots or Windows drives; filter directory names; select the current directory; and review the absolute path before explicit submission. See [#134](https://github.com/devemit/sylvops/issues/134) and the [directory browser source](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-tui/src/directory_browser.rs).
- **Cross-platform directory-browser hardening.** Hidden directories are initially omitted and toggled with `h`; links/reparse points are distinguished; roots, drive changes, unreadable or concurrently removed directories, bounded listings, truncation, and cancellation are handled without recursive repository scanning. See [#135](https://github.com/devemit/sylvops/issues/135).
- **GitHub browsing modal.** Uppercase `G` opens the selected Project's GitHub modal while lowercase `g` keeps its existing diff action. `i`/`p` switch Issues/Pull Requests, `j`/`k` navigate, Enter opens detail, `r` refreshes, `/` filters, `o` opens the validated browser target, and Escape moves back or closes. See [#126](https://github.com/devemit/sylvops/issues/126) and the [TUI GitHub modal](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-tui/src/github_modal.rs).
- **Issue-driven Start Work and recovery in the TUI.** `s` on an Issue opens the same daemon-owned preparation flow used by Desktop. The TUI exposes linked-work reuse, explicit parallel Worktrees, partial-success recovery, Retry Session, Work Source status/details, and transition to the new terminal attachment. Pull Requests do not offer Start Work in this release. See [#129](https://github.com/devemit/sylvops/issues/129).

### Shared daemon and CLI behavior

- **Read-only GitHub gateway through `gh`.** The daemon uses an already installed/authenticated GitHub CLI, treats GitHub.com and enterprise hosts separately, bounds subprocess output/deadlines, and stores no credentials. GitHub content is read-only: preview.6 does not create, edit, label, comment on, close, or otherwise mutate remote Issues or Pull Requests. See [#123](https://github.com/devemit/sylvops/issues/123), [#124](https://github.com/devemit/sylvops/issues/124), and the [gateway source](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-daemon/src/github.rs).
- **New read-only CLI commands.** `sylvops github status [--project <id>]`, `sylvops github list --project <id> ...`, and `sylvops github view --project <id> [--kind issue|pull-request] <number> ...` expose bounded diagnostics, filtered lists, and details. List/view support explicit refresh and bounded pagination. See the candidate's [`GithubCommand`](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-cli/src/main.rs).
- **Bounded, non-persistent remote data.** Lists use cursor pagination with at most 50 items per page and a bounded in-memory cache lasting no more than 60 seconds; explicit refresh bypasses the cache. Issue/PR bodies, comments, searches, filters, generated prompts, and additional instructions are not persisted. See [#124](https://github.com/devemit/sylvops/issues/124) and [#130](https://github.com/devemit/sylvops/issues/130).
- **Persisted identity, not content.** New migrations persist only explicit Project-to-GitHub repository associations and Work Source identity for Issue-created Worktrees. See [`0007_project_github_associations.sql`](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-daemon/migrations/0007_project_github_associations.sql) and [`0008_work_sources.sql`](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/crates/sylvops-daemon/migrations/0008_work_sources.sql).
- **Safe Start Work boundary.** The daemon revalidates the Project, GitHub association, Issue, local base commit, branch, and provider capability before mutation. It does not fetch automatically, silently reuse/reset an existing branch, or destroy a successfully created Worktree if Session startup fails. See [#127](https://github.com/devemit/sylvops/issues/127) and [#128](https://github.com/devemit/sylvops/issues/128).

## Explicitly not part of preview.6

The implemented feature is intentionally read-only on GitHub. GitHub mutations, Pull Request checkout/review workflows, background GitHub polling, GitHub notifications, automatic fetch, and storing GitHub credentials remain out of scope. Claude is still available for ordinary Session creation, but the preview.6 Issue **Start Work** flow is Codex-only because Claude's `task_bootstrap` capability is false in the candidate source. These boundaries are documented in the candidate [README](https://github.com/devemit/sylvops/blob/4c5753a6bf965451ae0ec4a80d9a1cd8e86f11c7/README.md).
